\begin{abstract}
When one agent in a multi-agent workflow produces a wrong fact, a stale lookup or
an injected instruction, every later step that read it is suspect, and some of
those steps have already acted on the world. \sys{} records, for every step, the
ordered \emph{(path, hash)} pairs it read from one namespace of messages, shared
state, files and tool results. Recovery re-executes the workflow and reuses every
step whose recorded reads still verify, and reconciles tool effects by intent.
The same provenance decides which \emph{tokens} a rerun must re-decode.
On four workloads with a local 7B model (574 live and 900 scripted cells for the
main grid, 113 more for follow-ups), selective recovery reruns 4.7 of 24 steps on
synthetic DAGs where restart reruns 22.5. On the live workloads it cuts recovery
wall time from 38.9\,s to 9.3\,s (booking, W1), 13.5 to 3.8\,s and 13.7 to
6.8\,s (two TAMAS scenarios) and 9.4 to 6.8\,s (code repair, W3), re-sends no
duplicate effects (restart: 0.6--2.0 per recovery), and a gate on irreversible
actions leaves 0 unauthorized actions in the 30 fault cells (5--7 without it).
The gate can hold good work, audits that follow provenance do \emph{not} beat
verifying everything, and on W3 selective recovery alone saves no time; we report
each claim with the verdict the data supports.
\end{abstract}

\section{Introduction}

Multi-agent LLM systems split a task across roles: a \emph{researcher} gathers
facts, a \emph{planner} decides, an \emph{executor} calls tools. Failures in such
systems rarely stay local~\cite{cemri2025why,huang2025resilience}: a hallucinated
room capacity becomes a booking, a booking becomes an e-mail
(Fig.~\ref{fig:example}). Once a faulty result has been identified, the operator
faces three questions:
(1)~\emph{propagation}: which later results and effects did it influence?
(2)~\emph{recovery}: what is the least work that restores a correct state?
(3)~\emph{safety}: which effects can be undone, and which must never be repeated?

The default answers are coarse. \emph{Restart} redoes everything and repeats every
side effect. \emph{Checkpoint rollback}~\cite{li2025agentgit} redoes the whole
time-order suffix after the fault, including work that never read the faulty
value. \emph{Always-verify} pays a model call on every output. Systems research
has better answers for other domains: build systems rerun a target only when an
input hash changed~\cite{mokhov2018build,mitchell2012shake}, intrusion-recovery
systems re-execute only actions that depend on an attack~\cite{kim2010retro}, and
sagas compensate effects that cannot be rolled back~\cite{garcia1987sagas}. We ask
whether those ideas carry over to LLM agents, whose steps are expensive,
non-idempotent and act on the world.

\paragraph{Contributions.}
\begin{itemize}
\item \textbf{Verifying traces over a hashed namespace} (\S\ref{sec:design}). One
  engine runs clean, faulty and recovery executions; a step is reused iff every
  recorded read hash still matches. Precision versus bookkeeping becomes a single
  depth knob.
\item \textbf{An intent-diff effect layer} with idempotency keys, compensation, an
  outbox and a trust gate, so recovery re-sends only effects whose intent changed
  and holds untrusted irreversible actions.
\item \textbf{Provenance inside a step}: speculative replay uses the faulty run's
  own output as a decoding draft; scoped, cached audits and cone-cost audit
  placement treat verification as graph nodes.
\item \textbf{A pre-registered evaluation} (\S\ref{sec:eval}) on four workloads,
  two ported from TAMAS~\cite{kavathekar2025tamas}, with a local 7B model on one
  laptop, comparing restart, rollback, always-verify and selective recovery under
  identical fault schedules, with every claim given a verdict.
\end{itemize}

\section{Problem Setting and Fault Model}
\label{sec:problem}

A \emph{workflow} is a set of steps run by agents; steps read and write state and
call tools. A run is \emph{correct} when its final outcome and every final
artifact equal those of the fault-free (``clean'') run. We inject one fault per
run at a chosen step: \emph{wrong} (a plausible but false value), \emph{stale} (an
outdated value), \emph{timeout} (a lookup that never returns), and
\emph{malicious} (an injected instruction, or a Byzantine agent).

We \textbf{separate detection from recovery}. Every recovery method is told the
identity of the faulty result, so recovery is judged on its own. Automated
detection (audits) is scored separately, with false positives and misses. A fault
that is read but changes nothing is flagged as non-propagating rather than counted
as robustness.

Tool effects carry MCP-style classes~\cite{mcp}: \texttt{read},
\texttt{idempotent}, \texttt{compensable} (a booking can be cancelled), and
\texttt{irreversible} (a sent e-mail stays sent). An irreversible effect sent before
the fault was known is \emph{leaked}, never recovered; an \emph{unauthorized}
action is a live irreversible effect that a malicious input caused.

\subsection{One namespace, Merkle hashes}
All state a step can touch is a node in one tree: messages (\texttt{/msg}), shared
state (\texttt{/kv}), files (\texttt{/fs}, backed by a git workspace whose tree
objects are already Merkle trees), tool results keyed by intent (\texttt{/world})
and audit verdicts (\texttt{/audit}). JSON values are subtrees, so
\texttt{/msg/planner/plan/agenda/items/2} is a valid path. Writes append MVCC
versions; a recovery run continues on a new branch, so the faulty and recovered
runs share every version they agree on.

A read is recorded as $(\mathrm{cut}(p,d), \mathrm{hash}(\mathrm{cut}(p,d)))$.
Because an ancestor's hash changes whenever anything below it changes, a coarser
cut can only over-invalidate, never miss a change. Four precision tiers are depth
cuts $d$ of the same tree (agent, step, artifact, field).

\subsection{Recovery as re-execution against a trace}
Every method runs the same loop (Fig.~\ref{fig:arch}). For each step in (dynamic)
workflow order, if the step is not marked dirty and all its recorded read hashes
match the current store, its writes are copied forward and its intents kept, with
no model call. Otherwise it reruns. Methods differ only in what they mark dirty:
\emph{restart} marks everything, \emph{rollback} the time-order suffix from the
fault, \emph{selective} only the faulty producer. Three properties follow for free: \textbf{early cutoff} (a rerun that reproduces
the same value stops propagation, as in Shake~\cite{mitchell2012shake}),
\textbf{write-set changes} (a key a rerun no longer writes hashes to $\bot$, so its
readers rerun, which a static graph would miss), and \textbf{branch flips} (steps
that no longer run become orphans and their effects are reconciled).

\subsection{Effects: intents, not undo-redo}
Each tool call becomes an intent keyed by $h(\text{step},\text{tool},\text{args})$.
After a rerun the old and new intent lists are diffed: identical intents are kept,
removed compensable ones are compensated, and irreversible ones are held in an
\emph{outbox} until the run commits. A \emph{gate} additionally holds irreversible
intents whose inputs carry an untrusted origin, until an audit clears them.

\subsection{Provenance inside a step and for audits}
\textbf{Replay.} A rerun step prefills its new prompt and feeds its old output as
a draft; tokens are accepted while the greedy argmax agrees, with n-gram
resynchronisation after a divergence (the LLMA idea~\cite{yang2023llma} applied to
the step's own output). Under greedy decoding the result equals a plain
decode~\cite{leviathan2023fast}, up to floating-point ties, which we re-verify
within a margin.
\textbf{Atoms.} Outputs are a canonical list of \emph{atoms} (one per input group,
each citing the paths it uses) plus an answer, so a changed input perturbs mainly
its own atom.
\textbf{Audits.} An audit checks one atom against only the values it read; its
verdict is stored in the namespace keyed by atom and source hashes, so only changed
atoms are re-audited. Trust labels on the origin of each value steer the checker.
\textbf{Placement.} An atom is audited when
$\mathit{risk}\times\mathit{cost}(\mathit{cone})+w\cdot[\text{reaches irreversible}]$
exceeds the audit cost, with risk from token confidence~\cite{fu2025deepconf}.

\section{Implementation}
\label{sec:impl}

\sys{} is about 7{,}200 lines of Python with 134 unit tests. The core uses only the
standard library with a SQLite journal. Real models run in-process through
\texttt{llama-cpp-python} on Metal, because replay needs per-position logits and
KV-cache cropping; output is grammar-constrained JSON at temperature~0. A scripted
model drives the large sweeps and the property tests.

\paragraph{Workloads.}
\textbf{W1} booking: researcher $\to$ planner $\to$ executor scheduling three
meetings over shared team facts (14 steps, 6 LLM calls; booking is compensable,
e-mail irreversible).
\textbf{W2} synthetic DAGs (24 steps) varying layers, fan-in, shared keys and effect
mix, scripted. \textbf{W3} a code fix in a git workspace checked by unit tests
(non-LLM file state). \textbf{W4} two TAMAS~\cite{kavathekar2025tamas} scenarios
ported as native workflows: Byzantine agents (\texttt{w4.byz}) and indirect prompt
injection (\texttt{w4.ipi}), whose effects are social-media posts.

\paragraph{Platform and runs.} One Apple M5 Pro laptop (24\,GB), Qwen2.5-7B-Instruct
Q4\_K\_M, greedy decoding, prompt cache off. Phase~1 ran 1{,}675 cells to measure
propagation. The Phase~2 grid was pre-registered and ran 574 live cells plus 900
scripted cells with zero errors; W3 recovery rows are a rerun of 50 cells after two
harness fixes (\S\ref{sec:experience}). A third, pre-registered run of 113 cells
(7B, 1.4\,h, zero errors) added the always-verify arm, two timeout faults and two
post-hoc fixes. Post-hoc changes are labelled as such wherever they appear.

\subsection{Selective recovery is faster and re-sends nothing}
\label{sec:e2e}
Selective recovery reruns fewer steps on all four workloads, and with replay it
cuts recovery wall time by 76\% (W1), 72\% (W4.byz), 50\% (W4.ipi) and 28\% (W3)
against restart (Fig.~\ref{fig:headline}a, Table~\ref{tab:e2e}). Without replay
the median selective-to-restart wall ratio is 0.58 [0.33, 1.00] on W1 and about
0.70 on W4; on W3 it is 0.94 [0.80, 1.06], so selective alone saves essentially no
time there and one fewer cell recovers (9/10). All 60 sampled reuse decisions were
canonical-equal to a scratch rerun (Wilson 0.94--1.0, effective $n\approx20$; no
samples on W3). W1 is correct in 8 of 10
cells for \emph{every} method: in repeat~4 the clean reference run itself fails the
workload's check in all ten cells, while each recovery reproduces that reference
exactly (values equal in 10/10), so this repeat separates no method.

\subsection{Reruns follow the cone, not the suffix}
\label{sec:p1}
On W2 (225 cells per method, fault position swept 0.1--0.9) restart reruns
\pmsd{22.5}{1.2} of 24 steps, rollback \pmsd{12.2}{6.0} and selective
\pmsd{4.7}{4.5} (Fig.~\ref{fig:cone}). Selective tracks the cone at every
position; rollback tracks the suffix, so its advantage over restart vanishes for
early faults. There are 0 unexplained out-of-cone reruns: in 14 cells selective
reruns a step outside the static cone, and every such step is new (the fault
changed control flow, 18 steps) or downstream of one (12 steps). Final values
equal the clean reference in 225/225 selective cells. The dynamic cone comes from the recorded read hashes, so this is partly
tautological; the independent check is the clean-run comparison. Finer cuts rerun fewer steps (agent
\pmsd{8.87}{4.56}, field \pmsd{6.27}{4.35}) and cost little: journal bytes per step
grow from 228 to 255, and on real runs
bookkeeping is 0.005\% of recovery wall time (max 0.057\%, 258 rows).

\paragraph{Fault kinds and stage.} The stage sweep is scripted (above). On the live
workloads, selective recovery on W1 reruns \vthreeStageWoneTeamRerun{},
\vthreeStageWoneCapRerun{} and \vthreeStageWoneAgendaRerun{} of
\vthreeStageWoneCapSteps{} steps when the faulty step is step
\vthreeStageWoneTeamPos, \vthreeStageWoneCapPos{} and \vthreeStageWoneAgendaPos{}

\subsection{Effect safety, and what the gate costs}
\label{sec:effects}
In Phase~1, naive restart on W1 compensates 3.0 bookings and re-sends 3.0
irreversible calls per recovery; with the intent diff these drop to
\pmsd{0.87}{0.92} and \pmsd{0.33}{0.49}. In the end-to-end cells, restart and
rollback create 0.83 duplicate effects per recovery pooled over all cells (0.6--2.0
by workload); selective recovery creates none (Fig.~\ref{fig:headline}b). Effects
already released before the fault was known stay leaked (W1: 1.8 per cell under
selective, 3.0 under restart). With the gate, unauthorized actions fall from
5 cells to 0 (Fig.~\ref{fig:headline}c). Always-verify alone does not help, with
7: detecting a flag without holding the action is not enough.

The gate is \emph{not free}. On W4.ipi the full stack recovers only 2 of 5 cells
because a held post is never released, and it holds a clean post in 2 of 3 clean
runs. The cause is the checker: a flag on a step that recovery reused keeps the
post held. A release rule that ignores such flags (post hoc, flag \texttt{release=on})
recovers \vthreeGateOkOn{} cells against \vthreeGateOkOff{} (restart
\vthreeGateOkRestart{}) with \vthreeGateUnauth{} unauthorized actions; one cell
still fails because a rerun step was re-flagged. Clean runs have no recovery, so
the gate still holds a post in \vthreeGateCleanOn{} of them, and on
\texttt{timeout\_item} the rule does not help (\vthreeTItemGateOk).

With resynchronisation a rerun decodes 0.19 (W1), 0.64 (W3), 0.42 (W4.ipi) and 0.21
(W4.byz) of a plain rerun's tokens. The median recovery LLM wall ratio is 0.38
[0.35, 0.44], 0.68 [0.56, 0.77], 0.70 [0.52, 0.88] and 0.50 [0.41, 0.67]
(Fig.~\ref{fig:replay}); 81/81 replayed calls are text-identical to a plain rerun,
with equal correctness in 36/36 pairs. This reverses our Phase~1 reading that
replay does not save wall time. One disclosure: the tie margin of
0.1 was set after a held-out call-level check failed at margin 0.0 (18/21
identical on 7B, 17/18 on 1.5B); at 0.1 it is 21/21 and 18/18. The break-even fault
rate (how often a fault must occur before atoms repay their clean-run cost) is 0.49
[0.33, 0.73] on W1, unbounded on W3, and 0 on W4 (atoms cost nothing there), so only
W1 is a non-trivial result.

\subsection{Audits do not beat verifying everything}
\label{sec:audits}
Trust labels fix detection of an injected agenda (without them the checker misses
it in 0/3 held-out runs, with them 3/3), but the probe's tokens make the trust-aware
audit dearer than always-verify (1588 against 1263 tokens on W1, 1188 against 738 on
W4.ipi), and on W4.ipi it raises 0.67 false positives per clean run. It also misses
wrong values (W3, W4.byz: 0/3), so over 15 fault cells it detects 8 where
always-verify detects 15. Cone-cost placement lowers tokens (734 on average against
889) at 0.53 detection; a budget-matched random baseline between uniform and
always-verify would detect 0.84 at the same budget. Held-out groups have $n{=}3$.

\section{Related Work}
\label{sec:related}

\textbf{Failures in multi-agent systems.} MAST~\cite{cemri2025why} catalogues
failure modes; failure attribution~\cite{zhang2025which} and resilience
studies~\cite{huang2025resilience} show detection is hard, which motivates scoring it
apart. TAMAS~\cite{kavathekar2025tamas} and A2ASecBench~\cite{li2026a2asecbench}
supply adversarial scenarios.
\textbf{Rollback for agents.} AgentGit~\cite{li2025agentgit} brings git-style
commits and branching to agent state, recovering in time order; we recover by
dependency and add effect classes. Sherlock~\cite{ro2025sherlock} places verifiers
and speculates ahead of them; SagaLLM~\cite{chang2025sagallm} adds saga-style
compensation. Dependency-guided rollback repair~\cite{wang2026rollback} and
REVISE~\cite{revise2026} already rerun only the dependent steps of an agent
workflow, so step-level selective rerun is \emph{not} our claim; ours is the
combination with shared state, an intent-diff effect layer that holds irreversible
actions, and provenance reused for decoding.
\textbf{Systems foundations.} Retro~\cite{kim2010retro} pioneered selective
re-execution for intrusion recovery; build systems contribute verifying traces and
early cutoff~\cite{mokhov2018build,mitchell2012shake}; lineage-based recovery dates
to RDDs~\cite{zaharia2012rdd}; sagas~\cite{garcia1987sagas} compensate long
transactions. \textbf{Decoding reuse.} Speculative
decoding~\cite{leviathan2023fast} and reference copying~\cite{yang2023llma}
accelerate generation with drafts; we use the faulty run's own output as the draft.
MiniCheck~\cite{tang2024minicheck} and DeepConf~\cite{fu2025deepconf} inform the
audit checker and risk score.

\section{Experience, Limitations and Dead Ends}
\label{sec:experience}

\begin{itemize}
\item \textbf{Dead ends: audits and the gate (\S\ref{sec:audits}, \S\ref{sec:effects}).} Trust-aware audits did not beat always-verify and the gate holds good work; we report both rather than tune them.
\item \textbf{A harness bug looked like a result.} Our first W3 numbers said restart
  matched the clean reference in only 4 of 10 cells. Restart did not undo the faulty
  edit before rerunning (so researchers read a patched file), and unittest reused a
  stale \texttt{.pyc} of the same size and second. After the fixes restart and
  rollback recover 10/10 and selective 9/10, so W3 no longer favours selective.
\item \textbf{The same ordering problem hid in selective recovery.} The one W3
  failure (\texttt{stale\_code}, repeat 0, all three selective arms) is an engine
  bug: a rerun researcher still listed the faulty run's edit, because that edit is
  compensated only when a later step reruns. We added an opt-in fix and a regression
  test; the 15 \texttt{stale\_code} cells rerun with it (post hoc, flag
  \texttt{revert=on}) recover \vthreeStaleAfter{} against \vthreeStaleBefore{}
  without it. The tables keep the unfixed rows.
\item \textbf{Floating-point ties break ``lossless'' replay.} Batched and sequential
  evaluation disagree on near-ties; the first replay matched plain decoding only
  87.8\% of the time. A local re-verification within a small logit margin
  restored identity (81/81), with the margin chosen after a held-out failure.
\item \textbf{Limits.} One 7B model, temperature 0, one laptop; held-out groups have
  $n{=}3$ and the end-to-end grid has 5 variants per cell, so intervals are wide.
  The fault-position sweep is scripted; live workloads have one to three fixed
  positions. Reuse validity has no W3 samples. Browser and VM state were not built;
  non-LLM state is a git workspace. Planner faults are not in the workloads.
\end{itemize}

\section{Conclusion}
Recording what each agent step actually read, as hashes in one namespace, turns
recovery into re-execution against a verifying trace. On a laptop-scale study this
reruns the dependency cone instead of the suffix; with replay it cuts recovery wall
time by 28--76\% on four workloads and removes duplicated side effects. Scoping
audits to provenance does not replace always-verify as a detector. The clearest
lesson is about irreversible effects: no recovery method can recall them, so a
gate before release is what prevents unauthorized actions, at the price of holding
some good work back.
